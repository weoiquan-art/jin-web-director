# Token Efficiency Guide

如何设计 prompt 和文档来最小化 token 消耗，同时保持清晰度。

## 📊 Token 成本对比

### 常见模式

| 方式 | Token 成本 | ❌ 不要 | ✅ 应该 | 节省 |
|------|----------|--------|--------|------|
| **列表** | 高 | 逐行完整句子解释 | 表格 + 符号 | 60-70% |
| **指令** | 中 | 长段落描述 | 数字列表 + 简短说明 | 40-50% |
| **代码** | 中 | 先解释后代码 | 直接贴代码 + 注释 | 50-60% |
| **参考** | 极低 | 重复内容 | 链接 + 简短摘要 | 80-90% |
| **决策** | 低 | 嵌套段落 | 流程图/表格 | 50-70% |

## 🎯 10 条 Token 节省法则

### 1️⃣ 用表格替代段落

❌ **差 (800 tokens)：**
```
项目色彩分为主色、次色和强调色。主色用于品牌和 CTA 元素，
通常是蓝色，值为 #007BFF。次色用于次要动作和链接，
通常是灰色。强调色用于错误提示和重要警告，通常是红色。
```

✅ **好 (250 tokens)：**
| 用途 | HEX | 用在 |
|------|-----|------|
| primary | #007BFF | 品牌, CTA |
| secondary | #6C757D | 次要动作 |
| error | #DC3545 | 错误提示 |

**节省：70%**

---

### 2️⃣ 建立项目缩写表并复用

❌ **差 (500 tokens)：**
```
在 background-color 属性中应用主要颜色...
在 margin-bottom 属性中应用中等间距...
在 font-weight 属性中应用粗体...
```

✅ **好 (150 tokens)：**
```
在 bg 属性中应用 primary...
在 mb 属性中应用 md...
在 fw 属性中应用 700...
```

**项目缩写定义（一次性 200 tokens）：**
| 缩写 | 含义 | 示例 |
|------|------|------|
| bg | background | bg-primary |
| mb | margin-bottom | mb-md |
| fw | font-weight | fw-700 |
| sm/md/lg | small/medium/large | sm=8px, md=16px |

**复用次数越多，节省越多。** 使用 5 次就回本。

---

### 3️⃣ 代码片段开即用（不需要解释）

❌ **差 (1200 tokens)：**
```
首先，你需要创建一个 HTML 结构，包含按钮元素。
然后，为按钮添加 class="btn btn-primary"。
接下来，添加 CSS 样式来定义按钮的外观...
最后，添加 JavaScript 来处理点击事件...
```

✅ **好 (400 tokens)：**
```html
<!-- Button -->
<button class="btn btn-primary">Click me</button>

<!-- CSS -->
.btn { padding: 1rem; border-radius: 8px; cursor: pointer; }
.btn-primary { background: var(--color-primary); color: white; }

<!-- JS -->
document.querySelector('.btn').addEventListener('click', () => console.log('clicked'));
```

**节省：67%**

---

### 4️⃣ 链接参考而不是重复内容

❌ **差 (600 tokens)：**
```
在你的项目中，有多个间距规则：
- 最小间距是 4px，用于...
- 小间距是 8px，用于...
- 中等间距是 16px，用于...
(重复整个间距系统)
```

✅ **好 (100 tokens)：**
```
见 design-system.md #spacing 了解间距规则。
```

**节省：83%**

---

### 5️⃣ 用符号和图标替代单词

❌ **差 (800 tokens)：**
```
对比度检查通过意味着文本颜色和背景颜色满足 WCAG 标准。
如果检查通过，你应该继续。
如果检查失败，你需要调整颜色。
在手机上，如果宽度小于 768 像素，你应该改变布局...
```

✅ **好 (200 tokens)：**
```
对比度 ✓ → 继续
对比度 ✗ → 调整颜色
宽度 < 768px → 单栏布局
宽度 ≥ 768px → 多栏布局
```

**常用符号：**
- ✅ ✓ ✗ ❌ (状态)
- ⭐ (优先级)
- ↓ → ← ↑ (流向)
- ├─ └─ (层级)
- 🔴 🟡 🟢 (红黄绿)

**节省：75%**

---

### 6️⃣ 决策树而不是嵌套解释

❌ **差 (900 tokens)：**
```
如果内容类型是导航，那么在手机上你应该使用汉堡菜单。
如果屏幕宽度大于 768 像素，那么可以改成水平导航。
如果不是导航，而是卡片列表，那么在手机上应该是 1 列...
```

✅ **好 (200 tokens)：**
```
内容是什么?
├─ 导航 → 375px: 汉堡 | 768px+: 水平
└─ 卡片 → 375px: 1列 | 768px: 2列 | 1440px: 3列
```

**节省：78%**

---

### 7️⃣ 最小化形容词和冗余词

❌ **差 (150 tokens)：**
"在项目中创建一个响应式的、现代化的、用户友好的页面设计..."

✅ **好 (50 tokens)：**
"创建响应式页面设计..."

**冗余词清单：**
- "非常/真的/确实" → 删除
- "也许/可能" → "应该" 或 "可以"
- "一般来说/通常" → 删除
- "某种方式" → 具体说明

**节省：67%**

---

### 8️⃣ 数字列表而非段落

❌ **差 (600 tokens)：**
```
首先确保你的页面在手机上看起来很好，这意味着
你需要检查文字大小、间距和按钮大小。其次检查对比度，
确保文字能被看清。最后测试交互，确保...
```

✅ **好 (150 tokens)：**
```
1. 手机适配：文字/间距/按钮
2. 对比度检查：≥ 4.5:1
3. 交互测试：按钮/表单/菜单
```

**节省：75%**

---

### 9️⃣ 模板和占位符而非编写多个版本

❌ **差 (1000 tokens)：**
```
按钮可以是 primary 按钮，代码是...
按钮也可以是 secondary 按钮，代码是...
按钮还可以是 danger 按钮，代码是...
(为每个变体重复代码)
```

✅ **好 (300 tokens)：**
```html
<button class="btn btn-{TYPE}">{LABEL}</button>
<!-- TYPE: primary|secondary|danger -->
```

**节省：70%**

---

### 🔟 一次性投入 + 高倍复用

**高投入文档（一次 2h）：**
- design-system.md (表格化系统)
- responsive-breakpoints.md (决策矩阵)
- component-patterns.md (代码模板)

**每次复用 token 节省：**
| 复用次数 | 每次查询节省 | 累计投入 token | 累计节省 token | ROI |
|---------|-----------|-------------|-------------|-----|
| 1 | 500 | 1000 | 500 | -1x |
| 3 | 500 | 1000 | 1500 | **+1.5x** |
| 5 | 500 | 1000 | 2500 | **+5x** |
| 10 | 500 | 1000 | 5000 | **+10x** |

**结论：** 3-5 次复用就完全回本，之后都是净收益。

## 📝 为 Agent 优化的 Prompt 模板

### ❌ 低效 Prompt (1200 tokens)

```
请帮我创建一个网站。网站应该有导航栏、英雄区、
卡片列表、表单和页脚。导航栏应该在手机上显示汉堡菜单，
在桌面上显示完整菜单。英雄区应该有背景图片和文字。
卡片列表应该在手机上是 1 列，在平板上是 2 列，
在桌面上是 3 列...（长段落描述）
```

### ✅ 高效 Prompt (400 tokens)

```
创建响应式网站。

结构：
1. navbar (汉堡-375px | 水平-768px+)
2. hero (单栏-375px | 双栏-768px+)
3. card-grid (1col | 2col | 3col)
4. form (1col | 2col-768px+)
5. footer

见 design-system.md, responsive-breakpoints.md
```

**节省：67%**

## 🎨 Agent 交流的缩写约定

建立项目级别的"shorthand"语言：

```markdown
## 项目通用缩写

| 术语 | 缩写 | 例子 |
|------|------|------|
| 响应式 | rwd | "rwd hero" = 响应式英雄区 |
| 小/中/大 | sm/md/lg | "btn-md" = 中等按钮 |
| 手机/平板/桌面 | 375/768/1440 | "375 单栏" |
| 无障碍 | a11y | "a11y 检查" |
| 令牌 | tk | "省 tk 方式" |
| 调用 | API | "API 集成" |

使用这些缩写时 token 成本降低 50-70%。
```

## 💡 实践检查清单

给 Agent 的文档：

- [ ] 用表格替代段落列表
- [ ] 建立缩写表并贴在文档顶部
- [ ] 代码块开即用（少于 3 行注释）
- [ ] 用链接而非重复整个系统
- [ ] 符号替代句子（✓ 而非 "成功"）
- [ ] 流程图而非嵌套说明
- [ ] 最少形容词（删除"真的""非常"等）
- [ ] 数字列表而非段落
- [ ] 模板和占位符
- [ ] 相同问题只解释一次，后续链接
