# 图像花园 + 局部 3D 水车入口

案例日期：2026-09-26。适用于固定镜位的品牌入口：保留已确认的场景质感，让其中一个物件真实旋转、受光并响应点击。先判断交互所需的空间自由度，再决定建模范围。

## 选择实现方式

| 用户要的体验 | 适合的实现 |
| --- | --- |
| 点击画面某处后进站 | 静态图 + 随裁切定位的按钮 |
| 水车真实转动，灯光随昼夜变化，镜位固定 | 无水车底图 + 独立 3D 水车 |
| 绕看物件、移动镜头、探索花园 | 评估全场景 3D；不要把固定机位案例直接扩成探索系统 |

本例用户明确选择建模。背景保留图片；水车用真实网格制作。不能把含水流、固定光影和透视的图片裁片直接旋转并称作建模。

## 制作顺序

1. 读现有项目说明、入口、渲染循环、主题、导航与部署配置。保留已有 shader 和作品数据链。
2. 从概念图移除待建模物件及它产生的水流/遮挡，补成干净底图。以同一底图制作夜景，避免分别生成两个不同布局。
3. 将 `Rotor`（轮圈、辐条、接水斗、轮毂）与固定轴、支架、引水槽分组。把转轴放在轮心；只旋转 Rotor。
4. 用独立材质表达木材、湿木与金属。分组内按材质合并几何，保留旋转组件；导出时校验节点、材质、尺寸和动画。
5. 昼夜保持同一几何、轴心和镜位，改变光照与场景背景。背景烘焙光和模型实时光需要一起看截图，不能只验证主题变量。
6. 提供显式入口按钮、物件点击区、暂停动态、减少动态行为和静态模型海报。进入后释放入口的 WebGL 资源，再启动已有作品场景。

网页粒子水流与真正流体模拟是不同能力。GLB 含什么、运行时额外做什么，应写在项目素材说明里。

## 裁切、触控和主题

- 对 `cover` 计算 `s=max(viewW/imageW,viewH/imageH)`，然后求实际图像尺寸、裁切偏移；把源图归一化坐标变换成屏幕坐标。不要把源图的 74% 直接当作所有设备的 74vw。
- 手机同时重排背景裁切与模型尺寸。底图移除了物件之后，模型可独立布局，但仍要在溪岸/地面附近接地。检查水车、路灯和文字是否相互遮挡。
- 两个昼夜按钮共用状态；首次跟随系统，手动选择持久化。存储受限时保留会话内切换。
- 主题要覆盖正文、索引、按钮、分隔、背景遮罩和降级目录；已有 shader 能通过颜色 uniform 适配时，不改核心逻辑。
- 未选中索引也必须可读。本例夜间截图暴露旧低透明度过暗，改为可读的最低透明度并增加 `aria-current`。
- 作品深链接可直接进入作品；从花园进入后的后退/前进须能还原两种场景。不要让入场状态覆写卡片 hash。

## 本例暴露的检查点

| 观察 | 修正与可复用检查 |
| --- | --- |
| 模型变暗了，背景仍是白天；夜图文件曾为空 | 检查文件字节、实际图片解码、`naturalWidth` 和切换后 opacity。存在文件名或图片请求成功不足以证明素材有效。 |
| 桌面路灯位置正确，手机被裁掉 | 使用统一坐标换算，并在手机独立取景；实测按钮完整包围盒和至少 44px 点击区域。 |
| 暂停或减少动态后仍需响应窗口缩放和主题 | 区分停止时间推进与必要重绘。用 dirty 状态让缩放、主题变化仍重绘。 |
| 花园与作品站均有 WebGL | 避免同时持续绘制；场景退出时清理帧循环、监听器、纹理、几何和 WebGL context。 |
| 同提交出现 Workers 失败与 Pages 构建 | 按项目实际部署路线逐项读取检查；“Worker 不存在”不能代替 Pages 构建结论，也不要因此切换部署栈。 |
